    15. Neural and representation models¶

    Prerequisites¶

    Read Chapter 11 for the logistic-regression and log-loss foundations this chapter directly extends, and Chapter 14 for the companion script's text branch, which shares a fixture with this chapter's neural branch. You should be comfortable with basic algebra, sums, and the chain rule of calculus in one variable; no matrix notation beyond writing out sums term by term is required. The notation registry fixes \(x\), \(\beta\), and \(\hat p\).

    Learning objectives¶

    By the end of this chapter you should be able to: derive the forward pass of a small feedforward network as a direct generalization of logistic regression; derive backpropagation's gradient computation using the chain rule on a network small enough to compute entirely by hand; explain how recurrent networks and attention address sequence-dependency problems that a plain feedforward network does not address, without claiming either is implemented in this book's companion; and state, with a concrete parameter count from the companion's own small network, why a deeper or wider architecture is not automatically better at the event counts typical of prediction-market research.

    15.1 A neural network is not a different kind of model, at first¶

    It is easy to introduce neural networks as something categorically different from the logistic regression of Chapter 11. A more useful framing, and the one this chapter builds from, is that logistic regression is already a neural network — one with zero hidden layers. A neural network with one hidden layer generalizes it by inserting one additional stage of nonlinear transformation between the input features and the output probability. Understanding exactly what that one extra stage adds, and what it costs in terms of the sample size needed to fit it reliably, is the entire content of this chapter.

    The companion script for this chapter, shared with Chapter 14, is text_and_neural.py:

    Command working directory: run this chapter's Python commands from book\companion. From the trading repository root, run Set-Location book\companion once first. The .venv belongs to that companion project; see companion setup.

    .\.venv\Scripts\python.exe examples\text_and_neural.py

    Its neural branch fits a small MLPClassifier with six hidden units on the same three numeric features as Chapters 11–12, not on text. The hand derivation below uses sigmoid hidden units to make a differentiable example easy to follow; the actual companion uses scikit-learn's default ReLU hidden units and a sigmoid binary output. Section 15.5 spells out that difference. The parameter-count and chain-rule principles apply to both, but their activation values and derivatives are not identical.

    15.2 The forward pass, derived from logistic regression¶

    Recall Chapter 11's logistic model: \(\hat p = \sigma(\beta_0+\sum_j\beta_j x_j)\), a single linear combination of the input features passed through the sigmoid function. A one-hidden-layer network computes several such linear-combination-plus-nonlinearity units in parallel, then combines their outputs with one more linear-combination-plus-nonlinearity step.

    Concretely, for input features \(x=(x_1,\ldots,x_k)\) and \(m\) hidden units, each hidden unit \(j\) computes

    \[ h_j = \sigma\Big(\sum_i W^{(1)}_{ji}x_i + b^{(1)}_j\Big), \]

    exactly Chapter 11's logistic form, with its own weights \(W^{(1)}_{j\cdot}\) and bias \(b^{(1)}_j\). The output stage then applies the same construction to the hidden-layer outputs:

    \[ \hat p = \sigma\Big(\sum_j W^{(2)}_j h_j + b^{(2)}\Big). \]

    Every sum here is an ordinary sum of products, computable term by term with nothing beyond arithmetic; "matrix multiplication" is simply a compact notation for writing many such sums at once, not a conceptually different operation.

    Work a fully explicit, tiny example: two inputs \(x=(0.6,-0.3)\), two hidden units, one output. Hidden-unit weights \(W^{(1)}_1=(0.5,-0.2)\), \(b^{(1)}_1=0.05\); \(W^{(1)}_2=(0.1,0.4)\), \(b^{(1)}_2=-0.05\). Pre-activation values: unit 1, \(0.5(0.6)+(-0.2)(-0.3)+0.05=0.41\); unit 2, \(0.1(0.6)+0.4(-0.3)-0.05=-0.11\). After the sigmoid: \(h_1=\sigma(0.41)=0.601088\), \(h_2=\sigma(-0.11)=0.472528\). Output weights \(W^{(2)}=(0.7,-0.6)\), \(b^{(2)}=0.1\): pre-activation \(0.7(0.601088)-0.6(0.472528)+0.1=0.237245\), giving \(\hat p=\sigma(0.237245)=0.559035\) (all values checked with a script). If this observation's true label is \(y=1\), the log-loss contribution is \(-\log(0.559035)=0.581544\) — the same log-loss formula used everywhere else in this book, now applied to a two-stage rather than one-stage model.

    15.3 Backpropagation: the chain rule, one layer at a time¶

    Fitting this network means choosing all the weights and biases to minimize average log loss over training data, exactly as in Chapter 11, except now there are two layers of parameters to adjust rather than one. Backpropagation is simply the systematic application of the chain rule to compute how the loss changes with respect to every parameter in the network, working backward from the output.

    RUMELHART1986 was inspected by the source audit on pp. 533-535 for its feed-forward setup, chain-rule equations, and illustrative discussion. Its objective is squared error, with gradient and momentum updates, not this chapter's log loss. The shared mechanism is propagating derivatives backward through differentiable layers. The paper discusses local minima as an obstacle to a global guarantee; it does not certify that an arbitrary finite optimization run reaches an optimum. It also acknowledges independently discovered variants rather than claiming exclusive priority. These are mechanism and source-scope statements, not evidence of calibration or market skill.

    For log loss with \(y=1\) and \(\hat p=\sigma(z_{\text{out}})\) where \(z_{\text{out}}\) is the output pre-activation, the gradient of the loss with respect to \(z_{\text{out}}\) has the same clean form Chapter 11 already established for logistic regression's gradient: \(\partial L/\partial z_{\text{out}} = \hat p - y\). With \(\hat p=0.559035\) and \(y=1\): \(\partial L/\partial z_{\text{out}} = -0.440965\).

    The gradient with respect to each output weight \(W^{(2)}_j\) follows from the chain rule, since \(z_{\text{out}}=\sum_j W^{(2)}_j h_j + b^{(2)}\), so \(\partial z_{\text{out}}/\partial W^{(2)}_j = h_j\), giving \(\partial L/\partial W^{(2)}_j = (\hat p-y)\,h_j\): \(-0.440965(0.601088)=-0.265059\) for the first output weight, and \(-0.440965(0.472528)=-0.208368\) for the second, with \(\partial L/\partial b^{(2)}=\hat p-y=-0.440965\).

    To reach the first-layer weights, continue the chain rule one layer further back. The gradient with respect to each hidden unit's pre-activation is \(\partial L/\partial z^{(1)}_j = (\hat p-y)\,W^{(2)}_j\,h_j(1-h_j)\) — the output-layer gradient, times that unit's contribution weight, times the sigmoid's own derivative \(h_j(1-h_j)\) evaluated at that unit's activation. Numerically: for unit 1, \(-0.440965(0.7)(0.601088)(1-0.601088)=-0.074015\); for unit 2, \(-0.440965(-0.6)(0.472528)(1-0.472528)=0.065945\) (values checked with a script). Each first-layer weight's gradient is then this quantity times the corresponding input: for unit 1's weight on \(x_1=0.6\), \(-0.074015(0.6)=-0.044409\); for unit 1's weight on \(x_2=-0.3\), \(-0.074015(-0.3)=0.022204\); and similarly for unit 2's weights, \(0.065945(0.6)=0.039567\) and \(0.065945(-0.3)=-0.019784\).

    This is the entire mechanism of backpropagation, exhibited completely on a network small enough to check by hand: repeated application of the chain rule, moving backward from the loss, at each layer multiplying by that layer's local derivative (the sigmoid's derivative \(h(1-h)\), at every hidden or output unit) and by the weight connecting to the next unit forward. A network with more layers or more units repeats exactly this pattern more times; no new principle is introduced by adding depth or width, only more terms to compute, which is why this is practically always done by automatic differentiation software rather than by hand once a network grows beyond a toy size.

    15.4 Sequence foundations: why recurrence and attention exist¶

    The network uses a fixed, ordered feature vector at one decision time: swapping signal and market_probability without also changing the weights changes the prediction. What it lacks is a modeled sequence axis or persistent hidden state across observations. Recurrent networks and attention address sequence relationships, without either being implemented in the companion.

    Recurrent networks process a sequence one element at a time, maintaining a hidden state that is updated at each step and carried forward to the next, so that information from early in the sequence can, in principle, influence processing much later. In practice, training such networks with a plain recurrent update tends to suffer from gradients that shrink (or occasionally explode) exponentially as they are propagated back across many time steps, making it hard to learn dependencies that span a long interval. HOCHREITER1997 introduces the Long Short-Term Memory (LSTM) architecture specifically to address this decaying-gradient problem, with reported experiments in the abstract on artificial sequence tasks constructed to expose exactly this long-dependency difficulty. Those artificial-task results are evidence that the architecture addresses the specific problem it was designed for; they are not evidence that an LSTM outperforms a simple probability model on the sparse, small-sample event data typical of this book's domain, where the number of independent events, not the length of any one sequence, is usually the binding constraint.

    Attention, and specifically the self-attention mechanism at the center of the Transformer architecture, takes a different approach: rather than processing a sequence strictly step by step, it lets every position attend directly to every other position, with a learned weighting. ATTENTION2017's Section 4 compares, for a sequence of length \(n\), the computational complexity per layer, the number of sequential operations required, and the maximum path length between any two positions, across self-attention, recurrent, and convolutional layers; a shorter maximum dependency path is the paper's argument for why attention can make long-range dependencies easier to learn than a strictly sequential recurrent update. The paper's reported applications are machine translation and parsing — genuinely sequence-structured, large-scale language tasks — not calibrated event-probability forecasting, and attention weights are not, by themselves, causal explanations or a form of independently verified evidence about what a model actually relies on.

    Neither recurrent networks nor attention is implemented here. The neural model uses one tabular row at a time; the text pipeline counts unigrams and bigrams, preserving adjacent two-word order but not a general sequence of documents or quotes. A reader extending to genuinely sequential inputs should first establish which temporal relationships the data and evaluation can support.

    15.5 The companion's small network, read honestly¶

    Run the companion script:

    .\.venv\Scripts\python.exe examples\text_and_neural.py

    The neural branch is MLPClassifier(hidden_layer_sizes=(6,), solver="lbfgs", alpha=2, max_iter=1500) after a training-fitted StandardScaler. The omitted activation argument defaults to ReLU: hidden activations are \(h_j=\max(0,z_j)\), with derivative one for positive pre-activation and zero for negative pre-activation (the implementation uses zero at the kink). Replace the sigmoid hidden derivative \(h_j(1-h_j)\) in Section 15.3 with that derivative when tracing the actual companion. Its binary output remains sigmoid. The full-batch quasi-Newton optimizer and L2 penalty are deliberately small-CPU teaching choices, not proof of reliable estimation at this sample size.

    Count the parameters this network actually has, using Section 15.2's structure with 3 input features and 6 hidden units: the first layer has \(3\times6=18\) weights plus 6 biases, and the output layer has \(6\times1=6\) weights plus 1 bias, for \(18+6+6+1=31\) parameters total. The companion's training cohort, recall from Chapter 11, is 89 events. Thirty-one parameters fit to 89 labeled observations is not an enormous model relative to its data by ordinary statistical standards, but it is a meaningfully larger and more flexible parameter space than Chapter 11's plain logistic model (4 parameters: one coefficient per feature plus an intercept, before any regularization), which is exactly why the heavier alpha=2 regularization is a deliberate, not incidental, choice here.

    On the fixture's 45 test events, the reported scores are Brier 0.193973 and log loss 0.575018 for this small neural network, compared with Chapter 11's logistic model's Brier 0.198372 and log loss 0.582490, and Chapter 14's TF-IDF logistic model's Brier 0.206632. The neural network's score is marginally better than the logistic baseline's on this one run. Report that difference for exactly what it is: a small gap, on 45 test events, from one seeded synthetic run, using models that all draw on closely related underlying information in this particular fixture. It is not evidence that a neural network is generally superior to a well-regularized logistic model at this scale, and it should not be read as license to reach for deeper or wider architectures on the strength of a difference this small.

    15.6 Small-sample warnings, and why "deeper" is not a default virtue¶

    The bias-variance framing already used for regularization in Chapter 11 applies with particular force to network depth and width. A model with more parameters can, in principle, represent a wider range of functions, which lowers achievable bias if the extra flexibility is genuinely needed — but it also raises variance, because more parameters generally need more data to estimate reliably, and an under-constrained fit on a small sample can latch onto sampling noise that looks like signal only in that particular training cohort.

    Prediction-market research typically works with dozens to a few hundred independent, dependence-grouped events for a given question family, not the millions of labeled examples that motivate very deep architectures in the domains where they have shown the clearest benefits. The calibration concerns already discussed for tree ensembles in Chapter 12 — GUO2017's finding that modern neural classifiers in large-scale image and document benchmarks were frequently miscalibrated — were themselves measured on datasets vastly larger than anything this book's domain typically offers; extrapolating "deep networks need calibration correction" or, worse, "a deeper network will forecast events better" from that literature to a sparse, small prediction-market sample is exactly the kind of unjustified transfer this book asks you to resist. The right question when considering a larger network is not "could it represent a richer function" (almost always yes) but "does this specific sample size support estimating that richer function's parameters reliably," and the honest default answer, at the sample sizes typical here, is that it frequently does not.

    A separate caution concerns optimization. The inspected backpropagation article discusses local minima and supplies no global-optimum guarantee. RUMELHART1986 Nor does a finite optimizer run guarantee that even a local optimum was reached: stopping tolerances, saddle regions, and iteration limits matter. Greater width changes the optimization landscape but does not imply a monotonic increase in troublesome local minima. Inspect convergence and distinguish a poor optimization run from inadequate architecture or insufficient data; one seeded fit cannot settle those explanations.

    15.7 Failure modes¶

    The observed Brier improvement is about 0.0044, a few thousandths, on 45 synthetic test events from one seeded run. It is a descriptive result, not established neural superiority. Three named tabular features are not themselves a temporal sequence; adding a sequence architecture without an appropriate representation and evaluation adds unsupported complexity. Under-regularization can fit noise, while heavier penalties also need validation. Benchmark findings from large image or text datasets do not automatically transfer to sparse event forecasting.

    Exercises and solution sketches¶

    Exercise 1: a forward pass by hand¶

    Using \(x=(0.6,-0.3)\), hidden-unit weights \(W^{(1)}_1=(0.5,-0.2)\), \(b^{(1)}_1=0.05\) and \(W^{(1)}_2=(0.1,0.4)\), \(b^{(1)}_2=-0.05\), and output weights \(W^{(2)}=(0.7,-0.6)\), \(b^{(2)}=0.1\), compute the hidden activations and the output probability.

    Solution sketch. Hidden pre-activations: \(0.41\) and \(-0.11\); activations \(h_1=\sigma(0.41)=0.601088\), \(h_2=\sigma(-0.11)=0.472528\). Output pre-activation: \(0.7(0.601088)-0.6(0.472528)+0.1=0.237245\); \(\hat p=\sigma(0.237245)=0.559035\).

    Exercise 2: one backpropagation step¶

    Continuing Exercise 1 with true label \(y=1\), compute \(\partial L/\partial z_{\text{out}}\) and the gradient with respect to \(W^{(2)}_1\).

    Solution sketch. \(\partial L/\partial z_{\text{out}}=\hat p-y=0.559035-1=-0.440965\). \(\partial L/\partial W^{(2)}_1 = (\hat p-y)\,h_1 = -0.440965(0.601088)=-0.265059\).

    Exercise 3: counting parameters¶

    A network has 3 input features, one hidden layer of 6 units, and 1 output unit, all fully connected with biases. Count the total number of trainable parameters.

    Solution sketch. First layer: \(3\times6+6=24\). Output layer: \(6\times1+1=7\). Total: \(24+7=31\).

    Exercise 4: why 31 parameters on 89 events warrants caution¶

    Explain, in terms of bias and variance, why fitting a 31-parameter network on 89 training events warrants a heavier regularization penalty than an unregularized fit, and why this concern would lessen if the training cohort instead had 89,000 events.

    Solution sketch. With only 89 labeled events, 31 free parameters have comparatively little data per parameter to constrain them, so an unregularized fit risks high variance: fitting sampling noise specific to this training cohort rather than a genuinely generalizable pattern. A strong penalty (the companion's alpha=2) trades a bit of fitting flexibility for reduced variance. At 89,000 events, each parameter has far more data supporting its estimate, so the same architecture could tolerate a lighter penalty without the same overfitting risk — the concern scales with the ratio of parameters to independent, dependence-grouped observations, not with the parameter count alone.

    Exercise 5: is the neural network's small edge meaningful?¶

    The companion reports neural Brier 0.193973 versus logistic Brier 0.198372 on the same 45 test events. A reader concludes "neural networks are the better choice for this problem." Evaluate that conclusion.

    Solution sketch. The gap (about 0.0044 in Brier score) comes from one seeded synthetic run on 45 dependence-grouped test events, using a fixture where all models draw on closely related underlying information; this is far too small and too under-replicated a comparison to support a general claim of superiority. A defensible conclusion would require repeated evaluation across multiple independent samples or resampling schemes, explicit uncertainty quantification, and ideally a demonstration that the gap persists outside this specific synthetic construction.
