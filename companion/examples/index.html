    Offline companion examples and public API¶

    Every executable example in this directory is original, deterministic, offline and synthetic/illustrative. None reports empirical prediction-market alpha. Every default stdout stream is a single JSON object with live_edge_claim: false. Decimal cash is serialized as strings, timestamps as aware UTC ISO-8601, and nonfinite scoring results as explicit strings such as "Infinity", not invalid JSON numeric constants.

    Run¶

    From the companion project root, book\companion, after the setup in the companion README:

    .\.venv\Scripts\python.exe examples\payoffs.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_companion_*.py" -v

Get-ChildItem examples\*.py |
    Where-Object { -not $_.Name.StartsWith("_") } |
    ForEach-Object {
        .\.venv\Scripts\python.exe $_.FullName
        if ($LASTEXITCODE -ne 0) { throw "Example failed: $($_.Name)" }
    }

    The targeted unittest command covers the companion modules and optional collector. Manuscript integrity checks live separately under book\tests. The companion command runs every one of the 17 example scripts in a fresh Python process with socket connection methods blocked. The small helper _support.py only constructs invented fixtures; shared accounting, fitting, scoring and decision logic live in the package.

    Optional public snapshots: separate from every default example¶

    Help performs no network request:

    .\.venv\Scripts\python.exe -m prediction_market_lab.market_data --help
.\.venv\Scripts\python.exe -m prediction_market_lab.market_data kalshi-markets --help
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_companion_market_data.py" -v

    After independently checking applicable terms, geographic/product access and permissions, an explicitly opted-in user can run a small current-only metadata acquisition:

    .\.venv\Scripts\python.exe -m prediction_market_lab.market_data kalshi-markets --acknowledge-terms --page-size 5 --max-pages 1 --output data\local-snapshots\kalshi-markets.snapshot.json
.\.venv\Scripts\python.exe -m prediction_market_lab.market_data polymarket-markets --acknowledge-terms --page-size 5 --max-pages 1 --output data\local-snapshots\gamma-markets.snapshot.json

    These are optional network commands, not commands run by the book's default examples or tests. They do not place orders. The acknowledgement is not proof of legal eligibility or permission to redistribute. Outputs must be new local files ending in .snapshot.json, which Git ignores.

    The other subcommands are kalshi-book --ticker <verified-ticker> and polymarket-book --token-id <verified-outcome-token-id>, with the same required acknowledgement and output flags. No identifier is automatically selected for you. Full request examples, checked official schemas, retry rules, native-field provenance and limits are in the optional snapshot documentation. Do not pass these native venue records into PaperBroker.

    Observed outputs for manuscript authors¶

    The following are observed synthetic outputs, not proposed results. They were generated on Python 3.12.6 with requirements.lock. Rounded model scores are useful for checking the run, never evidence of a live edge.

    Script Observed central result and negative case
    payoffs.py Cost 4.10; binary profits 5.90 / -4.10; modeled EV at 0.55 1.40; resale profit 0.40. Fractional 0.5 settlement gives 0.90 profit and null binary label; fractional label scoring rejected.
    bayes_scoring.py Prior 0.2, likelihoods 0.8/0.1 produce posterior 0.666667. Single-YES Brier 0.075. Wrong certainty has "Infinity" natural log loss; impossible evidence and NaN forecasts rejected.
    lmsr.py B=10, initial marginal probabilities 0.5/0.5; ten-YES trade costs 6.201145, not 5. Invalid zero liquidity rejected.
    point_in_time.py 360 rows, 180 events; 89 training, 44 validation and 45 test events; boundary/label-late groups toy-0089 and toy-0134 purged. A late observation is unavailable and rejected.
    forecast_models.py Held-out 45-event Brier: reference 0.249699; invented market 0.207439; logistic 0.198372; boosted 0.220607; validation-calibrated boosted 0.2672; fixed equal ensemble 0.224694. Calibration makes this tiny toy run worse.
    text_and_neural.py Train 89/test 45 events; 21 text vocabulary entries. TF-IDF logistic Brier 0.206632; six-hidden-unit network 0.193973. Templates are not evidence of real news understanding.
    execution_replay.py Initial reserve 2.30; finite fills 2 at 0.40 and 1 at 0.44; two units remain. Reusing the snapshot fills zero additional units. After cancel, cash 1.73, basis 1.27, inventory 3. Double-spend, naked sell and overfill rejected.
    constraints.py Compatible 10-unit YES/NO basket costs 9.50, floor payout 10.00, floor profit 0.50, conditional on both fills. Low capital and incompatible rules rejected.
    market_making.py Favorable supplied round trip realizes 0.40. Adverse path has -1.70 bid-liquidation marked profit, then -4.10 realized at NO settlement. No fill is inferred from touch.
    risk.py Quarter-Kelly fraction of cash spent is 0.059322 under the stated 0.55/0.41 binary assumptions. Below-cost belief sizes zero. Two correlated NO positions lose 8.20; the second position fails a 5.00 total commitment cap.
    policy_learning.py Learned actions (wait, buy) by context. Held-out same-simulator IPS reward per round 0.091175; adverse-selection-shift reward -0.088825. Missing off-policy support rejected.
    paper_session.py Only fresh, explicit inputs become a paper candidate. Stale/missing/ambiguous/invalid inputs return NO_TRADE. Paper buy leaves cash 5.90; equity at exit bids 9.60; marked profit -0.40, realized profit zero.
    quickstart_pattern.py Fixed market bins contain 30/15 test events, observed rates 0.333333/0.933333, market Briers 0.223735/0.174846. All live-edge inference rejected despite an attractive pattern.
    quickstart_event.py First test event toy-0135, rounded ensemble forecast 0.200542: both the 0.40 and 0.95 invented asks produce NO_TRADE. These new illustrative books are explicitly not historical execution records for that event.
    quickstart_consistency.py A three-state partition is screened at four units; five units fail displayed depth. If only the first leg fills and loses, realized profit is -1.24.
    quickstart_market_making.py Ten bought/zero sold units; liquidation marked profit -1.70. An additional positive-modeled-edge bid is stopped by the total risk budget.
    first_trade_checklist.py DO_NOT_PROCEED_FROM_SYNTHETIC_EVIDENCE; manual eligibility/rules/evidence/cost/risk checks remain unverified. Accounting-only maximum binary loss 4.10. No funded-order code exists.

    The forecast example's two updates for toy-0135 are 0.258916 at 12 hours and 0.258227 at 3 hours. These are a frozen latest-horizon model rescored on two invented snapshots, not a fitted sequence model or validated early- horizon calibration claim. Both observations share a single realized event.

    Paper screening uses the broker's remaining depth after earlier fills, not the original displayed quantities. Basket required_cash covers conservative reservations for submitting all legs before execution; it can exceed the modeled aggregate fill cost because of limit prices and per-fill rounding. Neither funding all orders nor passing a screen makes their execution atomic.

    Library modules and public entry points¶

    Module Main types/functions and boundary
    validation decimal, money, price, quantity, notional, probability, utc, parse_utc, available. Cash rejects float input; features need publication and observation by the cutoff.
    contracts Contract, Settlement, Side, Level, OrderBook, FeeSchedule; sweep_cost, executable_limit. USD 1 classroom payouts, finite depth, whole units and explicit invented fees, not venue adapters.
    accounting PaperBroker(cash, fees, max_quote_age=...); register, submit, status, cancel, take, synthetic_fill, observe_resting, settle, mark, reconcile, validate_book. Only in-memory paper orders; cash and sell-unit reservations, FIFO basis, immutable fill/ledger views.
    scoring brier_score(y,p), log_loss(y,p), calibration_bins, bayes_update, blend, regression_metrics. Single-YES Brier and exact natural-log endpoints; no hidden evaluation clipping.
    lmsr cost(q, liquidity_B), prices, trade_cost(q, delta, liquidity_B). Stable log-sum-exp classroom market maker; not an exchange book.
    data EventRow, TemporalSplit, generate_recurring, write_recurring, load_recurring, latest_per_event, grouped_chronological_split, teaching_split. Explicit clocks and whole-group cutoff purging.
    models feature_matrix, fit_forecaster(split) -> FittedForecaster, FittedForecaster.predict(rows), evaluate_forecaster, fit_text_and_neural. Training-only preprocessing, separate validation calibration, preset small CPU models.
    risk RiskBudget, Decision, screen_buy_yes, fractional_kelly, Exposure, scenario_stress. Model-conditional long-YES arithmetic and explicit joint losses; no empirical inference.
    constraints BasketLeg, BasketResult, scan_basket, payoff_dominates. Explicit manually verified event/rule/state compatibility, not semantic title matching or atomic basket execution.
    operations PaperInputs, paper_decision. Fail-closed stale/missing/ambiguous input checks; returns a decision record without creating an order.
    evidence Evidence, EvidenceGate, assess_evidence, synthetic_evidence. All synthetic cases rejected; even complete real-data declarations require independent research review and cannot authorize live trading.
    policy LoggedAction, simulate_logged_policy, learn_tabular_policy, ips_value. Toy wait/buy contextual bandit, known logging propensities, explicit support checks; no funding or execution simulator.
    reporting emit(title, result), json_value. Stable explanatory JSON; original cash precision retained.
    market_data Optional SnapshotClient(acknowledge_terms=True), kalshi_markets, kalshi_book, polymarket_markets, polymarket_book; RequestPolicy, write_snapshot, and python -m prediction_market_lab.market_data. Public GET acquisition only; no coupling to models or PaperBroker.

    Limitations and downstream real-data work¶

    See the data dictionary and integration contract before using any model or schema with real observations. Particularly:

    • Current snapshots cannot reconstruct earlier feature vintages or executable depth. A real collector must be independently checked against current official APIs and keep raw-response provenance.
    • The only optional network module, market_data, is an explicitly gated public-snapshot collector. The default examples never invoke it. No credential loading, funded-order endpoint, wallet signing or live switch exists.
    • Ledger reconciliation is an internal consistency check, not exchange reconciliation; the ledger is not persisted across Python processes.
    • Synthetic maker events and instantaneous taker fills are explicit assumptions. No empirical fill rate, queue model, cancellation latency, alpha, fee schedule or profitability claim is supplied.
    • Fractional Kelly, joint-scenario stress, manually supplied compatibility and boolean evidence declarations are teaching interfaces, not automatic verification of real contracts or a sufficient investment process.
    • Real-data researchers can directly reuse the score functions. Adapting EventRow or PaperBroker to richer metadata, venue collateral, fractional quantities and actual costs requires explicit validation and new tests; do not silently coerce incompatible data.
