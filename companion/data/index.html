    Data and reproducibility¶

    What is and is not included¶

    fixtures\recurring_events.csv is entirely synthetic, generated for this original book. It is not downloaded, anonymized exchange data, a news archive, or an empirical prediction-market performance sample. The neighboring provenance.json records its origin. There are 180 invented events and 360 rows: two observations sharing each event's single binary outcome.

    All 17 default examples are offline, deterministic teaching demonstrations. Their JSON explicitly says SYNTHETIC / ILLUSTRATIVE and live_edge_claim: false. Scores, inferred model probabilities, paper profits, bandit rewards, favorable basket calculations, and losses in those examples have no empirical market-performance interpretation.

    No third-party observations, externally written bulletin, or paid-model output is used in these synthetic fixtures. Their calendar and contractual identifiers are invented. The separate real NOAA extract contains attributed government observations, and its completed experiment preserves acquisition records, frozen results, and retrospective-data limitations.

    Reproduce the environment and fixture¶

    Run all commands in this guide from the companion project root, book\companion, as described in the companion setup. From the trading repository root, first run Set-Location book\companion.

    The initial environment was Python 3.12.6 on Windows, CPU only. requirements.lock was generated by pip freeze --exclude prediction-market-lab after installing the declared package. It contains version-pinned runtime dependencies, not an editable absolute local path. It is a portable version lock, not a wheel/hash lock: platform wheels and floating-point library builds can differ. The build frontend/backend is not frozen by this runtime lock.

    python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install -e . --no-deps
.\.venv\Scripts\python.exe -c "from pathlib import Path; from prediction_market_lab.data import write_recurring; write_recurring(Path(r'data\fixtures\recurring_events.csv'))"
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_companion_*.py" -v
.\.venv\Scripts\python.exe examples\payoffs.py

    For a simpler unpinned setup, installing -e . directly from this companion directory resolves the supported dependency ranges in pyproject.toml. Use the lock when reproducing documented numerical model results.

    The generator uses Python's random.Random(20260910). For each event it draws a latent value uniformly on [-1.5, 1.5], forms a logistic probability with coefficient 0.9, and draws one Bernoulli outcome. Signal noise has standard deviation 0.8 at the 12-hour horizon and 0.4 at the 3-hour horizon. The invented market forecast is 0.5 + 0.11 * signal + Gaussian(0, 0.06), bounded to [0.05, 0.95]. Recorded signal and forecast values round to six decimals. Template text describes that noisy signal, not the realized outcome. The latent probability is not offered to a fitted model as a feature.

    Recurring-event schema¶

    Every timestamp is an aware UTC ISO-8601 string. All prices in this file are forecast benchmarks, not executable bids or asks.

    Column Type and meaning
    event_id Invented realized-event identifier, toy-0000 through toy-0179.
    group_id Dependence-group identifier; equals event_id here. Both snapshots must stay together.
    family_id invented-recurring; identifies the shared synthetic template, not an additional independent label.
    event_time Invented event occurrence, daily at 18:00 UTC.
    published_at Invented bulletin publication, ten minutes before the decision.
    observed_at Invented local receipt, two minutes before the decision.
    decision_at Invented decision, twelve or three hours before the event.
    label_available_at Invented outcome availability, twelve hours after the event. This is not necessarily settlement time.
    signal Finite noisy synthetic explanatory variable.
    horizon_hours 12.0 or 3.0, nonnegative finite hours to the event.
    market_probability Invented noisy benchmark YES probability, bounded to [0.05, 0.95].
    outcome One integer 0/1 label per event, repeated across snapshots. Never a fractional payout.
    text Original invented bulletin template, derived from available signal.
    synthetic Literal True; explicit provenance flag, not inferred from filenames.

    EventRow.features_available() requires both publication and observation at or before the decision. grouped_chronological_split purges a whole group if it straddles a cutoff or its labels are not available at the relevant cohort cutoff. The training cutoff is April 1, the calibration cutoff May 16, and final retrospective evaluation cutoff July 1, 2025, all at 00:00 UTC. The last observation of each event is the predeclared model/scoring unit. The early snapshot is retained for temporal-update demonstrations, not counted as another independent realized event.

    Model preprocessing and fitting use only the training cohort. Isotonic calibration uses only the next validation cohort; test labels are used only for retrospective scores. Isotonic output is bounded to its fitted range when inputs are out of range; evaluated probabilities are not silently clipped away from 0/1. Thus a wrong certain prediction has infinite natural log loss, rendered as the JSON string "Infinity". Small validation samples can make this happen; it is an intended lesson, not hidden by the reporter.

    Other deterministic fixtures and economics¶

    The small books and user-supplied fills in examples\_support.py and the execution/market-making scripts are original in-memory fixtures. Their fixed clock is 2025-07-01T12:00:00+00:00; their identifiers and rule descriptions are not venue instruments. examples\policy_learning.py uses seed 11 for 800 training rounds and seed 12 for two 800-round comparison logs. The shared bandit generator's default seed is 20260910.

    The canonical fee is an invented USD 0.01 per unit per fill, not a Kalshi or Polymarket schedule. FeeSchedule can also express an invented notional-rate component. Total fees round up to cents once per fill. Trade notional rounds half-up to cents once per fill; whole-unit quantities and four-decimal price/payout grids are classroom conventions. Separate fills can cost differently from an aggregate fill. Pending buys reserve a conservative one-unit-fill cash bound. Sales reserve owned units; naked sales, overfills and consuming another buy order's reserve are rejected. There is no assumed settlement fee; a real experiment must explicitly model any applicable one.

    Taker replay consumes the finite displayed depth of an identified snapshot. Reusing the same snapshot cannot replenish its depth. A newly identified snapshot is an explicit external assertion of new observed liquidity; callers must not rename stale data to fabricate replenishment. Instantaneous taker execution is a disclosed paper assumption, not historical evidence. Resting quote touches never cause a fill. Maker fills require an explicit user-supplied synthetic event and must respect the limit and remaining size.

    The ledger is single-process, in-memory and long-only, with FIFO cent cost-basis allocation. It is not a persistent production broker, concurrent matching engine, OMS, tax ledger, or venue-specific collateral model. mark requires fresh, sufficient remaining bid depth and subtracts hypothetical exit fees. A mark changes no cash, inventory, or realized profit. Fractional exceptional settlement is a payout record whose binary_label is None, not a 0.5 training target.

    Integration contract for real-data experiments¶

    No default example performs network access. The separate, optional market_data module implements four allowlisted public snapshot GETs, described below. It preserves native fields instead of presenting changing fee schedules, fractional venue quantity grids or product rules as equivalent to the classroom broker. Additional real-data adapters require their own verification against current official documents. The primary indexes are https://docs.kalshi.com/llms.txt and https://docs.polymarket.com/llms.txt. The implemented scope is only the four snapshot endpoints below, not either venue's full API.

    • Keep raw-response provenance, endpoint/product, request parameters, UTC observation time, pagination and applicable permissions. Use public read-only GETs with bounded timeouts and explicit errors if acquisition is needed. Never add credential loading or funded-order capabilities here.
    • Do not label a retrieved current snapshot as a historical vintage. Price history is not a full executable order-book/fill history.
    • Use scoring.brier_score, scoring.log_loss, and scoring.calibration_bins for finite binary forecasts; report independent event counts and your weighting scheme. regression_metrics is available for a separately justified continuous target, not to blur fractional payout and binary label.
    • EventRow supports synthetic=False for honestly documented real rows, but it represents a recurring binary-event schema with one feature-publication clock. For heterogeneous sources, preserve each feature's own publication and observation times before constructing a validated row. It does not manufacture missing vintages or validate source claims.
    • grouped_chronological_split and TemporalSplit separate train, validation and retrospective test cutoffs. Dependence groups are supplied by the researcher. Broader common-shock dependence still needs an explicit inference method; grouping by event alone is not a universal cure.
    • fit_forecaster is a small preset numerical teaching pipeline, not an automated search, financial performance backtest, or guaranteed best model.
    • PaperBroker accepts only USD classroom contracts, whole quantities and explicit fills. Do not coerce incompatible real venue quantities, payout currency, fees or settlement into it without extending and testing the schema and stating the assumptions.
    • assess_evidence rejects synthetic data and missing evidence. Even if all evidence declarations are true, it returns RESEARCH_REVIEW_REQUIRED, never a live recommendation. These declarations must be independently audited; toggling booleans does not establish evidence.

    Optional public venue snapshots¶

    Do not acquire or share venue data before checking applicable current terms and permissions. Public accessibility is not a redistribution license. The source audit did not establish unrestricted venue-data redistribution rights. --acknowledge-terms records an explicit user acknowledgement, not a legal eligibility determination. Access restrictions, 401/403/451 responses, unavailable books and changing schemas are reasons to stop, not to authenticate, change geographic routes or bypass controls.

    The collector is separate from all 17 offline examples and from the NOAA real-data study. Nothing calls it by default, import has no network effect, and running the module without a subcommand fails before any network call. No live venue payload is committed with this implementation. Endpoint and schema documents were inspected on 2026-09-10; transport, pagination and error behavior were tested using original mocked responses, not by claiming successful live acquisition.

    Supported public GETs and native fields¶

    Subcommand Exact endpoint and selected query fields Preserved response and interpretation
    kalshi-markets https://external-api.kalshi.com/trade-api/v2/markets; limit, cursor, status, optional series_ticker / event_ticker Native markets and cursor envelope, ticker/event identity, lifecycle state, market type, rules, native _dollars/_fp strings and all extra metadata. Filter status is not assumed to use the same vocabulary as returned lifecycle state.
    kalshi-book https://external-api.kalshi.com/trade-api/v2/markets/{ticker}/orderbook?depth=20 orderbook_fp.yes_dollars and .no_dollars, each containing [price_dollars, count_fp] string pairs. Both sides are bids; quantities remain fractional strings. No synthetic asks, fills or integer-unit coercions are inserted.
    polymarket-markets https://gamma-api.polymarket.com/markets; limit, offset, closed, fixed order=id&ascending=true Native array of Gamma market objects; IDs, questions, condition/rule metadata, collateral hints, all extra fields. clobTokenIds, outcomes and outcomePrices remain JSON-encoded strings, not reordered or silently translated into the SDK's different envelope.
    polymarket-book https://clob.polymarket.com/book?token_id={token_id} Native market, asset_id, timestamp, hash, bids/asks with string price/size, min_order_size, tick_size, neg_risk, last_trade_price, and extra fields. Returned asset_id must equal the requested token. Timestamp remains its native digit string.

    Discovery validation checks the consumed envelope and market identity; book validation checks the consumed native decimal-string shapes and required fields. Unknown fields are preserved, not discarded. This is a small subset validator, not a claim of complete OpenAPI conformance or verification of contractual correctness. A scalar Kalshi market in metadata is retained as scalar, never turned into a binary training label.

    The Polymarket endpoints are the Predictions Gamma/CLOB product, not Polymarket US, Perps, or a guarantee that a native collateral token equals cash USD. Neither collector infers fees, rounding, settlement rules, eligibility, fills or historical availability. No returned native record is converted into PaperBroker, its fee schedule, or its quantity grid.

    Commands¶

    Offline inspection and focused tests:

    .\.venv\Scripts\python.exe -m prediction_market_lab.market_data --help
.\.venv\Scripts\python.exe -m prediction_market_lab.market_data polymarket-book --help
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_companion_market_data.py" -v

    Optional acquisitions, only after your independent permission checks:

    .\.venv\Scripts\python.exe -m prediction_market_lab.market_data kalshi-markets --acknowledge-terms --page-size 5 --max-pages 1 --output data\local-snapshots\kalshi-markets.snapshot.json
.\.venv\Scripts\python.exe -m prediction_market_lab.market_data polymarket-markets --acknowledge-terms --page-size 5 --max-pages 1 --output data\local-snapshots\gamma-markets.snapshot.json

$Ticker = "REPLACE-WITH-A-VERIFIED-DISCOVERED-TICKER"
.\.venv\Scripts\python.exe -m prediction_market_lab.market_data kalshi-book --ticker $Ticker --depth 20 --acknowledge-terms --output data\local-snapshots\kalshi-book.snapshot.json

$TokenId = "REPLACE_WITH_A_VERIFIED_OUTCOME_TOKEN_ID"
.\.venv\Scripts\python.exe -m prediction_market_lab.market_data polymarket-book --token-id $TokenId --acknowledge-terms --output data\local-snapshots\clob-book.snapshot.json

    The placeholders are not real instrument identifiers and must be replaced; the token placeholder is intentionally rejected by input validation. Discovery does not automatically select a supposedly compatible contract or outcome. A selected Gamma token must be interpreted with its market's outcome list, rules and product context.

    Optional common flags: --timeout 10, --max-bytes 2097152, --retries 1. Kalshi discovery supports --status open|unopened|closed|settled, --series-ticker and --event-ticker. Polymarket discovery uses closed=false by default; --closed selects closed records. These are current responses even when the records describe settled events.

    Programmatic equivalent:

    from prediction_market_lab.market_data import RequestPolicy, SnapshotClient

# Only run after independently checking applicable permissions.
client = SnapshotClient(
    acknowledge_terms=True,
    policy=RequestPolicy(timeout_seconds=10, retries=1),
)
snapshot = client.kalshi_markets(page_size=5, max_pages=1)

    Construction without explicit acknowledge_terms=True fails. Even the standalone HTTP transport requires explicit acknowledgement. No method accepts credentials, custom headers, arbitrary endpoint roots or arbitrary HTTP methods.

    Bounds, pacing and failure semantics¶

    • Defaults: 20 metadata records per page, one page, 20 Kalshi levels per side, 2 MiB per response, 10-second socket timeout, one additional attempt after a retryable failure. No polling loop or automatic book acquisition follows discovery.
    • Hard local caps: 100 records per page, 10 pages, 100 Kalshi levels per side, 4 MiB per response, 30-second socket timeout and two retries. Depth zero/unbounded Kalshi requests are refused. CLOB /book does not expose this depth parameter; its full returned body must fit the byte cap or acquisition fails rather than truncating the JSON.
    • Requests within one client are spaced at least one second apart. Retryable statuses are 429, 500, 502, 503 and 504; bounded network/socket failures can also retry. Backoff is at least one second, then two seconds. A valid Retry-After seconds value or HTTP date is honored. A malformed value, or a requested delay exceeding the default 30-second wait budget, aborts rather than retrying prematurely.
    • Timeout is applied to socket operations, with a deadline checked between bounded body chunks. It is not an OS-level hard DNS deadline. Content-Length and streamed bytes are both bounded. Compressed responses are refused after requesting identity encoding.
    • Only exact HTTPS hosts, routes and supported query parameters are accepted. All redirects are refused before a second request, including redirects to another allowed host. No cookies, authentication handler, environment proxy credentials or user-supplied headers are loaded. Direct verified-TLS connections only; networks requiring proxy configuration are unsupported, not worked around.
    • HTTP failures propagate. There is no synthetic fallback. CLI acquisition failure exits nonzero and writes no success snapshot. Library SnapshotError retains completed pages and attempt metadata in memory for inspection if a later page fails.
    • Kalshi cursors are treated as opaque query values, never URLs. Repeated cursors cause an error. Gamma uses the documented offset /markets endpoint, not the newer keyset endpoint. Full final pages at the local limit are marked possibly truncated; a short Gamma page or terminal Kalshi cursor marks that response sequence exhausted.
    • Mutable pagination is not a transactionally consistent universe. Duplicate IDs are preserved and reported; gaps remain possible. Even an exhausted traversal does not establish a complete historical dataset. A finite-depth Kalshi book separately flags omitted levels as possible.

    Saved snapshot schema and archival meaning¶

    Each output is a new file ending in .snapshot.json, inside the current working directory. Existing files are not overwritten. The companion's .gitignore excludes that suffix everywhere and data\local-snapshots\ entirely. Do not force-add or redistribute snapshots without applicable permission.

    The bundle contains:

    • format, classification, venue, product, endpoint, snapshot_scope: CURRENT_ONLY, historical_point_in_time: false, publication_history: UNKNOWN, and live_edge_claim: false.
    • Explicit acknowledgement plus eligibility_or_redistribution_rights_verified: false.
    • schema_reference: documented API version, official documentation URLs, inspection date and deliberately limited schema-validation scope.
    • started_at_utc, completed_at_utc, configured request_policy, and attempts recording requested URL, fixed GET method, local times, HTTP/error status and retry delay where applicable.
    • pages: exact requested URL; UTC receive time; unknown publication time; safe response metadata such as Content-Type, Date, ETag and Last-Modified; byte count; original response bytes encoded as Base64; SHA-256 of those exact bytes; parsed native payload; and a distinct SHA-256 of the sorted, compact, UTF-8 parsed JSON representation. Raw bytes are authoritative for original JSON numeric spelling. The canonical payload hash does not imply a venue signature.
    • pagination: page and record counts, configured cap, explicit truncated/more_records_possible, completion reason, continuation cursor or offset, and duplicate IDs preserved.
    • Requested Kalshi book depth, depth-truncation warning, and the explicit absence of complete book history.

    Keep a source's native timestamp, local receive time, HTTP Date, Last-Modified and any metadata updatedAt separate. None automatically supplies the historical publication time of every returned field. A stored current snapshot can support a future prospective record; it does not retroactively become a historical vintage or an executable-profit record.
